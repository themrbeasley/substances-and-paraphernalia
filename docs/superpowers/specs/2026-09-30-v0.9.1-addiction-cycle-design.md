# v0.9.1: Make the addiction cycle work (Design)

**Status:** draft, awaiting review
**Date:** 2026-09-30
**Sources:** [`tasks/SP-MODULE-TODO-2026-09-30.md`](../../../tasks/SP-MODULE-TODO-2026-09-30.md), [`reports/live-test-2026-09-30-v14.md`](../../../reports/live-test-2026-09-30-v14.md), the v6 lifecycle design page (`.superpowers/brainstorm/312-1778682818/content/corrected-lifecycle-v6.html`, outside the repo), [the v0.8.1 lifecycle spec](2026-05-13-v0.8.1-lifecycle-refactor-design.md).

## 1. In plain words

The addiction cycle (take a drug, maybe get hooked, try to quit at each Long Rest, go through withdrawal) has not worked in normal play since v0.8.1. After this release, a player sees this:

1. **Taking a drug.** Roll a Constitution save. Pass: the high. Fail: the high, plus the Addicted condition. Every dose raises tolerance, and tolerance weakens later highs. A character who is already addicted skips the save and just gets the high.
2. **Each Long Rest while addicted,** a window asks, drug by drug: take a dose, or abstain.
3. **Abstaining.** A Wisdom check to resist the craving. Fail: you give in and take a dose. Pass: a Constitution save; fail it and withdrawal starts (a timed penalty with a red glow around the screen).
4. **During withdrawal,** the same window keeps asking. Abstaining needs only the Wisdom check. Taking any dose ends the withdrawal, and you stay addicted.
5. **When the withdrawal runs out, the addiction ends.** Magic that cures Poisoned, the GM deleting the effect, and the Remove Addiction and Remove Withdrawal macros are the other ways out.
6. **Out of doses?** The empty drug stays in the inventory at 0 doses, so the window still shows it and the character has to abstain.

The gear bonuses work (+2, advantage, limited daily uses), removal macros remove only what they say, and the broken duplicate compendium entries are gone.

## 2. Design decisions

Each call names its reason. The user settled D3; the rest follow from the written history and from keeping the rules coherent.

| # | Decision | Why |
|---|---|---|
| D1 | "Addicted to X" means the character has X's Addiction effect. | It's the only thing the player can see. The v0.8.1 spec and `runPhase2`'s own comment already say this; the code read the wrong record. |
| D2 | The actor's hidden `withdrawal` record means only "in withdrawal from X right now". | That's what every correct writer already used it for; only drag-to-inventory and Simulate Dose misused it. |
| D3 | Finishing withdrawal ends the addiction. | The user's call, on 2026-09-30. It's also step 8 of the v6 design and the drugs' original "until withdrawal completes" text. |
| D4 | Quitting order is v6's: willpower first. Fail = relapse (take a dose). Pass = Constitution save; fail = withdrawal. | With D3, today's order (fail willpower, then roll Constitution) makes failing your willpower the way to get clean. v6 and the May willpower note (old todo, Item 3) both say fail = relapse. |
| D5 | Out of doses: skip the willpower check and roll the Constitution save. | Unchanged. There is nothing to relapse onto. |
| D6 | Already in withdrawal: abstaining is the willpower check only. Pass = hold the course, and tolerance decays. Fail = relapse. Out of doses = hold the course, no roll. | A second withdrawal on top of the first makes no sense. v6 also had "passed + withdrawing: recovery progresses". |
| D7 | Any dose taken during withdrawal (relapse, choosing Use, or using it by hand) cancels the withdrawal but not the addiction. | Otherwise a character could keep using through withdrawal and still come out clean. |
| D8 | Withdrawal removed by the GM or the Remove Withdrawal macro counts as finishing it. A relapse is the only removal that does not cure. | The Macros page already calls Remove Withdrawal a "magical detox". One rule is easier to remember than two. |
| D9 | Tolerance rises on every dose: pass, fail, bypassed, or already addicted. | v6 and the v0.8.1 spec both say so. With D1, addicts skip the save, so tolerance-on-pass-only would mean they never build tolerance or risk overdose. |
| D10 | One dose runs in order: (1) gear bonus and addiction save, skipped if already addicted; (2) the high, weakened by current tolerance; (3) tolerance +1; (4) overdose check. | The first dose gets the full high (the curve is 100% at tolerance 0). Overdose gates on the new total (v6). Today the save and the overdose check run as two separate hooks with no fixed order. |
| D11 | The last dose leaves the drug at 0 doses instead of deleting it. Using a drug at 0 doses is blocked with a notice. | The Long Rest needs the drug's rules to run the out-of-doses branch, and using the last dose is the most common moment to start quitting. dnd5e already restocks an empty item when the same drug is dropped from the compendium. This applies to every module drug, which is predictable and keeps the tolerance history. |
| D12 | The module applies the high itself, weakened by tolerance. Shipped drugs stop listing the high on their activity, so Midi-QoL and the chat card no longer apply a second full-strength copy. | That's the only way the tolerance scaling runs, and it ends the pile-up of highs. |
| D13 | Kept as today: a failed save still gives the high, and the Long Rest window still defaults to "take a dose". | v6 and the May spec disagree on the first; neither is in this release's scope. |

**Accepted limits:**

- If the GM deletes a drug item outright, that drug's Long Rest row is skipped (its rules are gone) and a warning is logged. Remove Addiction still works.
- A character who passes the Constitution save stays addicted with no symptoms, and faces the choice again next Long Rest.
- A drug with addiction on but withdrawal off can only be cured by magic, the GM, or a macro. No shipped drug is set up that way.
- Addiction is tracked per inventory item. If a second copy of the drug lands as a separate item (for example, from a world item rather than the compendium), the two don't share an addiction.
- A GM authoring a new drug who adds the Altered effect to the activity's effect list gets a double high when Midi applies its copy after ours. The Authoring page gets a warning. The module does replace any copy that is already on the actor when it applies its own.

## 3. Changes

File paths are relative to the repo root. "Record" below means the actor flag `flags["substances-and-paraphernalia"].withdrawal` or `.tolerance`.

### 3.1 Who is addicted (todo item 1)

- `scripts/data/flag-schema.js`: add `getAddictedSubstanceIds(actor)`, the distinct `sourceSubstanceId`s of the actor's `addiction`-role effects (built on `findEffectsByRole`).
- `scripts/hooks/addiction.js` `rollSaveAndApply`: the already-addicted check reads the Addiction effect, not the record. The already-addicted branch posts the existing "Maintained" line and applies nothing (D1 guarantees the effect exists).
- `scripts/hooks/long-rest-abstain.js` `runPhase2`: rows come from `getAddictedSubstanceIds`. Each row also carries `inWithdrawal` (the record has an entry). A missing item is skipped with a `logger.warn`.
- `scripts/hooks/drag-to-inventory.js`: **Addicted** applies the Addiction effect only; no record. **Withdrawing** applies the Addiction effect (unless already present) and a full withdrawal. Its local copies of `applyAddictionEffect` and `findAddictionTemplates` are deleted in favour of `addiction.js`'s, which also honours the Poisoned coupling setting the copy ignored.
- `scripts/ui/simulate-dose.js` `preSeedAddictionState`: **addicted** gives the Addiction effect only (today it also adds a permanent withdrawal). **withdrawing** gives the Addiction effect plus a withdrawal already half elapsed.
- **One withdrawal applier.** `applyWithdrawalEffect(actor, item, { elapsedSeconds = 0 } = {})` in `addiction.js` replaces the three current copies (`addiction.js applyWithdrawalEffect`, `long-rest-abstain.js applyWithdrawalAeFromTemplate`, `drag-to-inventory.js cloneWithdrawalAesOntoActor`). It resolves templates (`withdrawal.effectIds`, then the `withdraw` name fallback, then `buildDefaultWithdrawalTemplate`), sets the duration to the authored seconds minus `elapsedSeconds` through `prepareEffectPayload`, and writes the record entry `{ appliedAt, endsAt }`. The public API name is unchanged.

### 3.2 Recovery and relapse (D3, D7, D8)

- `scripts/hooks/withdrawal-cleanup.js` (GM-arbitrated, as today): when a withdrawal effect is deleted and it was the **last** withdrawal effect for that drug on the actor, clear the record entry. Then, unless the delete options carry `fishutRelapse: true`, delete the drug's Addiction effects with `{ fishutIntentional: true }` (so the linked-isolated guard lets them go) and post "{actor} has come through withdrawal from {item} and is no longer addicted."
- `scripts/hooks/addiction.js` post-use handler: if the actor has withdrawal effects for this drug, delete them with `{ fishutRelapse: true }` and post "{actor} takes {item} during withdrawal; the withdrawal ends, but the addiction does not."

### 3.3 The quitting rolls (D4 to D6)

- `scripts/data/abstain-branch.js` (new, pure): `abstainBranch({ forced, inWithdrawal, willpowerPassed })` returns `"relapse" | "hold" | "withdrawal-save"`:

  | forced | inWithdrawal | willpower | result |
  |---|---|---|---|
  | yes | no | (not rolled) | withdrawal-save |
  | yes | yes | (not rolled) | hold |
  | no | either | failed | relapse |
  | no | no | passed | withdrawal-save |
  | no | yes | passed | hold |

- `long-rest-abstain.js` `runAbstainBranch` rolls the willpower check when not forced, asks `abstainBranch`, then: **relapse** → `forceUseSubstance` (the full dose chain, which cancels any withdrawal); **hold** → tolerance decay plus a chat line; **withdrawal-save** → the Constitution save (when withdrawal is enabled), with withdrawal on a fail. Tolerance decays on a passed willpower check and on every forced abstain, as today.
- `scripts/ui/abstain-dialog.js`: rows in withdrawal show an "in withdrawal" tag, so a player can see that taking a dose throws the progress away.

### 3.4 One dose, in order (D9, D10, D12)

- `addiction.js` `onPostUseActivity` becomes the only post-use handler for drugs. For every module drug: relapse check (3.2) → addiction save if enabled (3.1, 3.5) → `applyAlteredEffectGated` → `incrementActorToleranceCount` → `rollOverdoseAndApply`. `applyOutcome` no longer bumps tolerance.
- `scripts/hooks/overdose.js`: drop its own `postUseActivity` listener and `registerOverdoseHooks` (and its call in `scripts/module.mjs`). `rollOverdoseAndApply` stays exported and in the API.
- `applyAlteredEffectGated`: the "remove prior high" filter also matches `altered`-role effects whose `origin` is the drug's uuid (the Midi-applied copy has no `sourceSubstanceId`).
- Content: all 18 drugs' activities drop the Altered effect from `system.activities.*.effects`.
- `tools/validate-content-checks.mjs`: warn when a substance activity lists an effect whose `aeRole` is `altered`.

### 3.5 Rolls that ignore bonuses (todo item 3)

dnd5e 5.3.3 reads `parts` only from `config.rolls[0]`, so top-level `parts` is silently dropped. Midi-QoL 14.0.12 wraps `rollSavingThrow` and recomputes advantage unless it's passed in explicitly.

- `addiction.js` `rollSave`: `{ ability, target: dc, advantage, rolls: [{ parts, options: { advantage } }], midiOptions: { advantage } }`, where `parts` is `[String(bonus)]` when there's a bonus. The dead legacy keys (`targetValue`, `fastForward`, `chatMessage`) go.
- `long-rest-abstain.js` `rollAbstainCheck` / `rollWithdrawalSave`: the actor bonus flags (`abstaining.check.bonus`, `withdrawal.save.bonus`) move into `rolls[0].parts`; `target` replaces `targetValue`.
- **Advantage is verified live.** If the retest still shows Normal in Midi's roll window, the fallback is to skip the roll window for bypass-granted advantage (`dialog.configure = false`), so the passed mode is used as is.

### 3.6 Gear lookup (todo item 4)

- `scripts/data/modifier-pipeline.js` `resolveSourceItem`: return `effect.parent` when it's an Item (item-transferred effects on V11+), and fall back to the existing `origin` walk otherwise.

### 3.7 Records that won't clear (todo item 2)

V14 dropped the `-=` delete syntax in favour of `ForcedDeletion`, and `setFlag` merges, so deleting a key from a copied object does nothing.

- `flag-schema.js` `clearActorWithdrawalEntry` and `clearActorToleranceEntry`: `actor.update({ [\`flags.${MODULE_ID}.withdrawal.${id}\`]: new foundry.data.operators.ForcedDeletion() })` (and the `tolerance` equivalent).
- Remove Withdrawal macro: the same form for orphan record rows.

### 3.8 Remove Addiction (todo item 6)

- Match `aeRole === "addiction"`, or no `aeRole` and a name matching `/addict/i`. Drop the record rows: the record isn't about addiction anymore. The macro deletes with `fishutIntentional`, so the linked-isolated guard allows it.

### 3.9 Bad ids (todo item 7)

- Rename to 16-character alphanumeric ids, and rename the files to match: the five `fhMacRemove*` macros, `fhParaOracleT01`, and the four bypass effects `fhAECalibInhByp`, `fhAENeurShntByp`, `fhAEDubsPipeByp`, `fhAEOracleTByp` (including the `_key` fields). Nothing else references them.
- `tools/validate-content-checks.mjs`: error on any `_id`, top-level or embedded, that isn't `/^[a-zA-Z0-9]{16}$/`.

### 3.10 Empty drugs stay (D11)

- `scripts/data/last-dose.js` (new, pure): `keepLastDose(updates, itemId)` removes `itemId` from `updates.delete` and pushes (or merges) `{ _id: itemId, "system.quantity": 0, "system.uses.spent": 0 }` into `updates.item`. It returns whether it changed anything.
- `scripts/hooks/activity-gating.js`: a `dnd5e.activityConsumption` listener calls `keepLastDose` for module drugs. The `preUseActivity` gate blocks a module drug at quantity 0 or below with a "no doses left" notice, before the gear check and with no "Use anyway".

### 3.11 Text and docs

- **18 drug descriptions,** Withdrawal paragraph, each with its own DCs and duration: "At the end of each Long Rest while addicted, you either take another dose or abstain. If you abstain, make a DC {abstain} Wisdom check to resist the craving; on a failure, you give in and take a dose. On a success, make a DC {withdrawal} Constitution saving throw; on a failed save, you suffer withdrawal for {duration}. If you have no doses left, skip the Wisdom check and make the saving throw. While in withdrawal, abstaining takes only the Wisdom check, and taking any dose ends the withdrawal but not the addiction. When the withdrawal ends, so does the addiction."
- `lang/en.json`: the willpower-fail line becomes a relapse line; new lines for hold, relapse-during-withdrawal, recovered, the "in withdrawal" tag, and "no doses left". Mind the prefix-collision invariant.
- **GM Guide journal** (`_source/fishut-journals`): the withdrawal and recovery rules.
- **Wiki:** Mechanics (the cycle; tolerance rewritten to the current count and curve model, replacing the retired v0.4 stack model; the stacking sentence removed), Macros (what each Remove macro now does), Authoring (don't list the high on the activity; the last dose stays).
- `CLAUDE.md`: the record's meaning, recovery and relapse, the consumption listener, the single post-use handler.
- `CHANGELOG.md`: a `[0.9.1]` entry.
- `tasks/SP-MODULE-TODO-2026-09-30.md`: record the decision and tick items as they land.

**Gates:** `npm run lint`, `npm run validate`, `npm run test:unit`, `npm run pack`.

**Live retest** (the `foundryvtt:live-test` skill, same world and versions as the V14 wave, starting from a real failed save and never a seeded state):
1. A fail gives the Addicted condition and the high. A second dose adds no second addiction, the tolerance count rises, and the high is weaker and replaces the first.
2. Long Rest: the window lists the drug. Abstain with a failed willpower check: relapse, a dose is spent. Abstain with a passed willpower check and a failed Constitution save: withdrawal, record entry, red glow.
3. Next Long Rest in withdrawal: the "in withdrawal" tag shows. Take a dose: withdrawal gone, addiction stays. Get back into withdrawal and pass the willpower check: hold.
4. Withdrawal expires (backdate the start, as in the V14 wave): record cleared, addiction removed, "no longer addicted" line.
5. Use the last dose: the item stays at 0; using it is blocked; the next Long Rest forces abstain. Drop the drug from the compendium: quantity refills and it can be used.
6. Bypasses: +N adds to the total, advantage rolls two d20s, and daily uses are spent. Gear of the wrong administration type grants nothing.
7. Remove Addiction lists only addiction effects. Remove Withdrawal ends the addiction. Orphan records clear.
8. Compendium: 6 macros and 12 paraphernalia, with no duplicates.
9. No deprecation warnings whose direct caller is this module.

## 5. Out of scope

- Overdose is off on every shipped drug (content pass).
- No shipped drug has a visible tolerance effect; players see tolerance only in the Long Rest window (content pass).
- Whether a failed save should still give the high (D13).
- Tracking addiction per drug rather than per inventory item.
