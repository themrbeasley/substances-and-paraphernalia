# v0.9.2: the v0.9.1 leftovers

**Status:** scope approved 2026-09-30. Source list: every deferred note from the v0.9.1 reviews, checked against the v0.9.1 code (48 open, 6 already fixed, 4 not bugs).

**Goal:** fix every open leftover that matters, switch overdose on for the performance enhancers, make tolerance visible, and bring the docs in line with the code. Release as v0.9.2 with the wiki.

## Decisions

Each decision says what changes for the table, then how.

### D1. Closing a roll window no longer skips the roll

Today a player who closes the addiction save window never gets addicted, and closing either Long Rest roll window (the Wisdom check or the Constitution save) skips that step. From now on, closing the window just means the module makes the roll without the window, with the same DC, bonus and advantage.

How: one pure helper, `rollWithoutSkipping(roll, config)` in `scripts/data/roll-config.js`. It calls `roll(config)`; if the result is empty (dnd5e resolves a closed window to `[]`), it calls `roll(config, { configure: false })` and returns that. Used by the addiction save (`addiction.js` `rollSave`) and both Long Rest rolls (`long-rest-abstain.js`). The `if (!roll) return` early exits become "no roll function" guards only. The dead `rollAbilitySave` fallback goes (dnd5e 5.3 only has `rollSavingThrow`). The old "roll window closed: nothing happens this rest" rule is retired. Midi-QoL's handling of `configure: false` is checked in the live test.

### D2. A blank DC means "no roll", and the cycle moves on

Today blanks read as 0: a blank Wisdom DC always passes (never relapses), a blank Withdrawal DC always passes (never withdraws, so never recovers), and a blank tolerance fade means tolerance never fades.

- Blank **Abstain (Wisdom) DC**: no Wisdom check; the character goes straight to the Withdrawal Save. `getAbstain` returns null unless `dc` is a finite number (not null, not ""); `abstainBranch` already handles "no check authored".
- Blank **Withdrawal DC**: no save to resist, so withdrawal sets in. This keeps recovery reachable (recovery only comes through withdrawal). `getWithdrawalDc` returns null for null and ""; the Long Rest skips the save and applies withdrawal when it is null. Tolerance and overdose already need a finite DC for their tier and keep doing nothing without one.
- Blank **tolerance fade**: use the default (1 per Long Rest). An explicit 0 still means "never fades".
- The content checker errors on a null or "" Abstain DC and Withdrawal DC in shipped content (it already rejects missing ones).

### D3. Simulate Dose uses the drug's own effects

The clone remaps every id in the plural lists (`addiction.addictionEffectIds`, `withdrawal.effectIds`, `tolerance.effectIds`, `overdose.effectIds`), so simulated withdrawal shows the authored effect and glow. The withdrawal template finder also falls back to the name match when its ids resolve to nothing, the same way the addiction finder does.

### D4. The dead "Tolerance Interaction" overdose setting is removed

The dropdown and magnitude on the drug sheet are deleted with their save code and text, along with the unused `overdose-interaction.js` and `data/overdose.js` and their tests and API entry. The overdose roll has used the tolerance threshold since v0.8.1; these controls never did anything since. Clean break, no migration (an old saved value is ignored).

### D5. Untagged highs are recognised by name

A hand-made drug whose "Altered by ..." effect has no role tag is now replaced on the next dose and its stray copies are blocked, like tagged ones. `isPriorHigh` accepts an effect with no role whose name matches /altered/i, the same fallback every other lookup uses.

### D6. Drag-to-inventory "Withdrawing" doesn't double up or half-apply

If the character is already in withdrawal from that drug, the second set is skipped (chat says so). If the drug has no Addiction effect to apply, the drag warns and does nothing instead of leaving withdrawal without addiction.

### D7. A paused Addiction effect still counts as addicted

A GM who switches an Addiction effect off (instead of deleting it) no longer makes the module treat the character as clean (which allowed a second Addiction effect on the next dose). "Addicted" now reads `actor.effects`, like every other lookup. One shared predicate (role tag, else name) decides what an addiction or withdrawal effect is, for both the addicted lookup and recovery.

### D8. Tolerance shows on the character

When a drug has no authored tolerance effect, the module adds a plain marker named "Tolerance to Coalshade Powder (2)" to the character's effects. It has no Changes, no statuses and no duration, so it changes nothing in play and shows no token icon. The count in the name updates on every dose and every Long Rest fade, and the marker goes away when tolerance fades to 0. An authored tolerance template still wins, and its name gets the same count suffix. The stale Details-tab text ("Auto-stack tolerance on addiction-save pass" and the tooltip about stacks and DC bumps) is rewritten.

### D9. Overdose is on for the six performance enhancers

Giantsbreath Tonic, Wyrmiron Salts, Black Lift, Ironhour Caps, Combat Cocktail and Reflex Injector each get an overdose block (`enabled: true`, `chancePercent: 10`, a one-line description) and an "Overdose" effect template: Poisoned and Incapacitated, 1 minute. With the tier table, the roll only happens once tolerance to that drug is at its cap (for example Black Lift at 2 doses of tolerance, Ironhour Caps at 5), then 10% per dose. GMs can tune or switch it off per drug on the sheet.

### D10. Remove macros show names as plain text

The five Remove macros escape every effect name, source id and label they put in their window (`foundry.utils.escapeHTML`), so a renamed effect can't run code on the GM's screen. Also: Remove Withdrawal includes cleared leftover records in its restore log, and Remove Addiction, Remove Tolerance and Remove Withdrawal say so when nothing was ticked.

### D11. Robustness

- **Dose steps fail separately.** Each of the five dose steps (relapse check, save, high, tolerance, overdose) runs in its own catch-and-log, so one failure no longer cancels the rest of a dose that is already spent. The Long Rest tolerance fade loop gets the same per-drug catch, so a failure can't stop the Withdrawal Choices window from opening.
- **Recovery tracking keys on the actor's uuid**, so two unlinked tokens of one character don't block each other.
- **No-GM recovery stays as is; the doc changes.** When no GM is online, owners' clients run recovery (so a player can still recover). CLAUDE.md's sentence is corrected to say so.
- **The recover / relapse / wait decision** moves into a pure helper with a test.
- **The last-dose guard** removes every delete of the drug, not just the first.
- **Permanent withdrawal** records `endsAt: null` instead of an end time equal to its start.
- **Naming and comments:** the already-addicted outcome is named "maintained" (it was "extended"). Stale comments and JSDoc are fixed in `addiction.js` and `activity-gating.js`.
- **API:** `onPreCreateActiveEffect` joins `api.addiction`.

### D12. Tests, tooling, version

Missing tests are added:
- forced abstain never relapses;
- `d20Config` with advantage and bonus together, and with a negative bonus;
- the clear-tolerance absent key;
- the source item from parent over origin;
- the altered-on-activity check with a non-Altered listed effect;
- `isStrayHigh` with no origin and with no items;
- `rollWithoutSkipping`;
- blank DCs;
- the recovery decision;
- the last-dose multi-delete.

The validator's activity label prints the id when the name is empty, and its header names the macro and journal scan. The test helper restores `globalThis.foundry`. Prettier is run on the files this work touches. `package.json` and `module.json` go to 0.9.2.

### D13. Docs match the code

- **README:** the Long Rest paragraph (resting client, game-time withdrawal, recovery), tolerance on every dose, the overdose threshold, and "18 drugs".
- **Home:** all six macros, and "withdrawal and recovery".
- **Mechanics:**
  - Only add and subtract values scale.
  - The master switch sentence doesn't cover the 0-dose block.
  - `overdose.chanceModifier` is an actor flag.
  - The closed-window and blank-DC rules from D1 and D2.
  - Overdose on the six drugs.
  - The tolerance marker.
- **Authoring:**
  - Plural effect-id keys.
  - The Details-tab field list rewritten to match the sheet (no "Required subtypes picker", no withdrawal modifier).
  - The overdose fields without Tolerance Interaction.
  - "Altered effects" plural.
- **Simulate Dose:** rewritten. It has two settings, runs the dose pipeline, and has no gear check.
- **Macros:** the overdose and Remove Withdrawal rows.
- **CHANGELOG:** a `[0.9.2]` entry and the 0.9.1 re-import sentence.

## Left as is

- The blocked-copy log stays debug-only: a line per blocked copy would flood the console for every old drug copy.
- Four notes were not bugs:
  - `updates.item` always exists alongside `updates.delete`.
  - The module only ever applies one tolerance template.
  - The plain-object drop branch can't reach the appliers.
  - `d20Config` callers always pass numbers.
