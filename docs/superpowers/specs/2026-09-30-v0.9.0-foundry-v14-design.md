# v0.9.0: Foundry V14 port (design)

- **Date:** 2026-09-30
- **Branch:** `claude/foundryvtt-plugin-v14-905176`
- **Status:** awaiting review

## In plain language

The module was built on Foundry V13 but never shipped there. The user now plays on V14. Most of the module already works on V14, because it was written against the newer Foundry APIs from the start. The exception is Active Effects: V14 changed how they store their changes, their durations, their start times and what happens when they expire. Foundry converts the old shapes automatically, but not everywhere, so several mechanics are broken or misbehave today. One of them (expired effects are no longer deleted) is a world-wide V14 change and gets fixed in the user's House Automation module instead. This release fixes the rest, drops V13 support, removes calls that Foundry will delete in V15/V16, and adds guards so those calls can't creep back in.

## Goals and success criteria

1. The module loads cleanly on Foundry V14 (build 368) with dnd5e 5.3.3, DAE 14.0.14, Midi-QoL 14.0.12 and Token Magic FX 0.8.4, with no console errors.
2. Every mechanic in the live test matrix below passes in a real V14 world.
3. **Zero deprecation warnings from our code.** Verified live by turning on Foundry's `CONFIG.compatibility` failure mode, filtered to our module's path, so any deprecated call from us throws instead of warning.
4. Lint and the content validator reject the V13-era shapes, so they can't come back.
5. V13 is no longer supported (`compatibility.minimum: "14"`).

## What changes

### A. Bugs on V14 today

**A1. Withdrawal never wears off.** V14 stores duration as `duration.value` + `duration.units`. Our withdrawal builders spread the template's duration and add `seconds`. The template already has `value: null` as its own property, so V14's converter leaves it alone and the effect is permanent.
Sites: `hooks/long-rest-abstain.js` `applyWithdrawalAeFromTemplate`, `hooks/drag-to-inventory.js` `cloneWithdrawalAesOntoActor`.

**A2. Tolerance no longer weakens repeat doses.** `refreshAlteredAe` in `hooks/addiction.js` rewrites `data.changes`. In V14 a template's `toObject()` has `system.changes`, so we write an empty `changes` array and Foundry ignores it because `system.changes` already exists. The Altered effect keeps full-strength values.

**A3. "Make permanent" no longer clears durations.** Several builders set `duration.rounds` / `duration.seconds` to `undefined` to make the effect permanent. In V14 those are no longer real fields, so the template's `value` / `units` survive. Visible today in drag-to-inventory: benefit effects keep their 10 to 60 minute timers instead of being permanent. Latent in the addiction and withdrawal builders (shipped templates have no duration, but an authored one would leak through).
Sites: `hooks/addiction.js` (`buildAddictionPayload`, `buildWithdrawalPayload`), `hooks/drag-to-inventory.js` (`applyBenefitEffects`, `applyAddictionEffect`).

**A4. Expired effects are no longer deleted (handled outside this module).** V14 core expires timed effects itself, on the active GM's client. Its default (`CONFIG.ActiveEffect.expiryAction = "update"`) **marks** them `duration.expired = true` and leaves them on the actor, greyed out. Times Up used to delete them. DAE 14's `expiryAction` setting only covers DAE's special durations. Our cleanup (`hooks/withdrawal-cleanup.js`) runs on `deleteActiveEffect`, so without deletion the withdrawal effect expires but the actor stays flagged as withdrawing.

This is a world-wide V14 behavior change, not specific to this module, so it's fixed in the user's House Automation module as a separate task (a switch that restores deletion). This module keeps relying on `deleteActiveEffect`. Consequence: in a V14 world without that switch (or `expiryAction = "delete"`), withdrawal flags don't clear on expiry. Acceptable pre-1.0 with no shipped users. Revisit before any public release.

**A5. A copied template can inherit a stale start time.** V14 stamps `start` (world time, combat, turn) when an effect is created on an actor, but it keeps any start keys the incoming data already has ("prefer user-defined duration data"). A template carrying an old `start.time` could expire the moment it's applied.

**A6. "Times Up is missing" on every GM login.** `integrations/index.js` still lists `times-up` as a known optional integration. Times Up can't be installed on V14, so the ready-time notice fires every session.

### B. Future-proofing: deprecated calls (work in V14, removed in V15/V16)

**B1. Change modes become change types.** V14 replaced numeric `mode` (0 to 5) with string `type` (`"custom"`, `"multiply"`, `"add"`, `"downgrade"`, `"upgrade"`, `"override"`). Reading `change.mode` or `CONST.ACTIVE_EFFECT_MODES` logs a warning until V16. Sites:
- `data/modifier-flag.js` `writeModifierAsChanges` / `mergeModifierIntoChanges`: emit `type: "override"`. Remove `OVERRIDE_MODE`.
- `hooks/addiction.js` `buildDefaultWithdrawalTemplate`: vignette row `type: "override"`.
- `integrations/dae.js` `aeRequiresDae`: detect `change.type === "custom"` instead of comparing against `CONST.ACTIVE_EFFECT_MODES.CUSTOM`.

**B2. `changes` moved to `system.changes`.** Read and write `system.changes` everywhere:
- `data/flag-schema.js` `getModifier` / `setModifier` (update with `{"system.changes": …}`).
- `ui/details-tab.js`: the five effect-creation payloads use `system: { changes }`.
- `hooks/addiction.js`: the default withdrawal template and the A2 attenuation.
- `integrations/dae.js`.

**B3. Global `renderTemplate`.** `hooks/drag-to-inventory.js` uses the bare global, which is removed in V15. Switch to `foundry.applications.handlebars.renderTemplate`, the way the rest of the module already does.

**B4. Change values can be non-strings.** V14's converter runs `JSON.parse` on legacy string values, so a world's existing bypass effect that stored `'["inhaled"]'` now holds a real array, and `"true"` becomes `true`. `decodeChangeValue` in `modifier-flag.js` must accept native arrays, booleans and numbers as well as strings. We keep *writing* strings, so the rows stay editable in the Changes table.

**B5. Lock-selector parity.** dnd5e 5.3.3's `_disableFields` added `FORMULA-INPUT`. Add it to `VIEW_MODE_LOCK_SELECTOR` in `ui/details-tab.js` so the "mirrors dnd5e" contract in CLAUDE.md stays true. We don't inject that element today; this is one token.

### C. One shared effect-payload helper (fixes A1, A3 and A5 in one place)

Nine builders across four files each copy a template the same way: `toObject()`, drop `_id`, merge our flags, set `origin`, clear `disabled`, and fiddle with duration. The V14 bugs live in each copy. Replace the copies with one pure helper in a new file, `scripts/data/effect-data.js`. It must be importable in plain Node for unit tests (no Foundry globals).

```js
// Read an effect's change rows (document or plain data).
export const effectChanges = (effect) => effect?.system?.changes ?? [];

// Turn template data (from toObject(), or a plain object) into a create payload.
// duration: undefined → keep the template's; null → permanent; number → that many seconds.
export function prepareEffectPayload(data, { sourceSubstanceId, origin, role, duration } = {}) { … }
```

`prepareEffectPayload` always:
- deletes `_id` and `start`, so V14 stamps a fresh start (fixes A5);
- merges `flags[MODULE_ID]` with `sourceSubstanceId`, plus `aeRole` when `role` is given;
- sets `origin` and `disabled: false`.

For `duration: null` (permanent) it sets `value: null, expiry: null, expired: false`. Clearing `expiry` matters: an effect with no value but an expiry event still counts as temporary in V14 and would expire at that event. For a number it sets `value: <seconds>, units: "seconds", expired: false`. Seconds keep the existing `endsAt` arithmetic and the "months = 30 days" rule. V14's native `months` are calendar months, and it has no `weeks`.

Callers and the duration each passes (current behavior is kept, only its V14 correctness changes):

| Builder | File | Duration | Role |
|---|---|---|---|
| addiction | `addiction.js` | `null` | `addiction` |
| altered (plus attenuation on `system.changes`) | `addiction.js` | keep | `altered` |
| tolerance marker | `addiction.js` | keep | `tolerance` |
| withdrawal (`applyWithdrawalEffect`) | `addiction.js` | `null` | `withdrawal` |
| withdrawal after the Abstain roll | `long-rest-abstain.js` | seconds | `withdrawal` |
| withdrawal clone | `drag-to-inventory.js` | seconds | `withdrawal` |
| benefit | `drag-to-inventory.js` | `null` | none (unchanged) |
| addiction | `drag-to-inventory.js` | `null` | `addiction` (was missing; the v0.7 contract says every module-created addiction effect carries it) |
| overdose | `overdose.js` | keep | `overdose` |

`buildWithdrawalPayload` keeps setting `transfer = false`. The overdose builder keeps its own name and description override, then passes through the helper.

### D. Times Up removal (fixes A6)

- `module.json`: drop the `times-up` entry from `relationships.recommends`.
- `integrations/index.js`: drop the `times-up` entry from `KNOWN_INTEGRATIONS`.
- `settings.js`: drop the `timesUpIntegration` world setting. It gates nothing. An orphaned stored value in a world is harmless.
- `lang/en.json`: drop the three Times Up keys.
- Code comments that credit Times Up with expiry now say expiry deletion comes from Foundry core with `expiryAction = "delete"` (House Automation's switch; see A4).

### E. Compendium content

Convert all 61 effects in `_source/` to the V14 shape with a **throwaway script** kept in the scratchpad, not committed:
- `changes` → `system.changes`;
- `mode` → `type` (the content uses 0 → `custom`, 2 → `add`, 5 → `override`);
- `duration.seconds` → `{ value, units: "seconds" }`, and legacy `rounds`, `turns`, `startTime`, `startRound`, `startTurn` and `combat` keys are dropped.

Change values stay as authored strings. A `git diff` check confirms nothing else moved, then `npm run pack`.

`tools/validate-content-checks.mjs` becomes the permanent guard. It reads `system.changes` and **errors** on any effect that still has top-level `changes`, a numeric `mode`, or a legacy duration key.

### F. Lint guard

In `eslint.config.mjs`:
- Remove the deprecated globals from `foundryGlobals` (`Dialog`, `Application`, `duplicate`, `mergeObject`, `expandObject`, `flattenObject`, `getProperty`, `setProperty`, `hasProperty`, `loadTemplates`, `renderTemplate`). Any bare use then fails `no-undef`.
- Add `no-restricted-properties` for `CONST.ACTIVE_EFFECT_MODES`.
- Add `no-restricted-syntax` (scripts only) for legacy duration reads (`duration.seconds`, `rounds`, `turns`, `startTime`, `startRound`, `startTurn`) and for `.changes` accessed on anything other than `.system`. Each message names the V14 replacement.

### G. Manifest, versions and docs

- `module.json`: `version` `0.9.0`; `compatibility` `{ minimum: "14", verified: "14.368" }`; dnd5e `{ minimum: "5.3.0", verified: "5.3.3" }`. There is no `maximum`, so V15 can try to load it.
- `CHANGELOG.md`: a v0.9.0 entry (breaking: V13 dropped).
- `docs/compatibility.md`: a "Foundry V14 + dnd5e 5.3.3" entry recording the findings above.
- `CLAUDE.md`: target versions; Times Up → core expiry, with the note that cleanup needs `expiryAction = "delete"` (A4); AE shape notes (`system.changes`, `type` strings, `value` / `units` durations, expiry marks rather than deletes); the new helper; the lint and validator guards; the TMFX and vignette sections switch from `mode: 0/5` to `type: "custom"/"override"`.
- `docs/wiki/Authoring.md`, `docs/wiki/Mechanics.md`, `README.md`, `docs/INTEGRATION-LICENSES.md`: the same Times Up and change-type wording.

## Testing

### Unit tests (plain Node)

- New `test/unit/effect-data.test.mjs` for `prepareEffectPayload`: keep / permanent / seconds; `start` and `_id` removed; `expiry` cleared on permanent; flags merged without dropping existing keys; role optional. Add it to the explicit `test:unit` list in `package.json`.
- Update the two existing tests that build change rows: `modifier-flag-shape` (`type` instead of `mode`) and `validate-content` (fixtures move to `system.changes`), plus any others the run flags. Add a decode case for native array and boolean values (B4), and validator cases proving the legacy shapes are rejected.

### Live test wave (the user's `foundryvtt:live-test` skill)

Setup needs the user to close Foundry. Then:
- move the installed v0.8.8 copy out of `Data/modules/` to a dated backup folder (moved, not deleted);
- build the packs in this worktree;
- create the `Data/modules/substances-and-paraphernalia` junction to the worktree;
- the user reopens Foundry, loads a world of their choice and signs in as Gamemaster.

Everything runs on throwaway actors in a scratch scene, and problems go to a report file, not mid-wave fixes. Before the matrix, set `CONFIG.compatibility.mode = CONST.COMPATIBILITY_MODES.FAILURE` with `includePatterns = [/substances-and-paraphernalia/]`, so any deprecated call from our code throws.

## Out of scope

- Native V14 duration units (showing "3 days" instead of seconds in the effect UI). A UX nicety that would complicate the months and weeks rules; seconds keep today's behavior.
- Writing change values as native JSON. Strings stay editable in the Changes table and match what the code writes today.
- A `getHeaderControlsApplicationV2` rewrite of the Simulate Dose patch. The current patch still works on V14.
