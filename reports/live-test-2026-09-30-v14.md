## Summary

**The V14 port works.** Every V14 change checked out live: V14 effect data (`system.changes`, string types, `value` + `units` durations), fresh start times, permanent effects without an expiry event, withdrawal in seconds, the Token Magic filter through DAE, the vignette, expiry deletion through House Automation, the drag-to-inventory dialog, Simulate Dose, the macros' new row text, the Subtype Manager, and no deprecated calls from this module.

**Pre-existing bugs found (not caused by the port), most severe first:**

1. **Withdrawal never starts in normal play.** Phase 1 never writes the actor's `withdrawal` map, and the Long Rest step only reads that map, so no Abstain dialog ever appears after a real addiction. The same empty map breaks "already addicted", so repeat doses stack addiction effects. (Row 8)
2. **Withdrawal map entries are never cleared.** `clearActorWithdrawalEntry` and the Remove Withdrawal macro save the map through `setFlag`, which merges, so removed keys stay. (Rows 9, 13)
3. **+N and advantage bypasses do not change the roll.** `rollSave` passes `parts` and `advantage` where dnd5e 5.x does not read them; chat still claims they applied. (Row 5)
4. **Bypass uses are never spent and gear `appliesTo` is not checked.** The source item is looked up through `effect.origin`, which is empty for item-transferred effects; the item is `effect.parent`. (Row 5)
5. **Tolerance never weakens repeat doses.** `applyAlteredEffectGated` is not called anywhere. (Row 6)
6. **Remove Addiction removes every module effect**, not only addictions. (Row 13)
7. **Invalid document ids in compendium content** (18 to 19 characters for five macros, 15 for Tongue of the Oracle) load as null ids and show as ghost entries. (Rows 1, 13)
8. **Minor:** Altered effects applied by Midi from the chat card have no `sourceSubstanceId`, so they stack with tolerance-applied copies. (Row 6)

**Test-method notes:** the `CONFIG.compatibility` failure trap caught dnd5e's own deprecations whenever this module rolled a save, and broke the first Midi workflow; it was replaced by recording each warning's direct caller. V14 dialogs are `<dialog>` elements with no `offsetParent`.
